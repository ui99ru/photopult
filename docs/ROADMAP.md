# Дорожная карта Фотопульта

Этапы из брифа. Принцип: **каждый этап — рабочее состояние, коммит, зелёный CI.**
Полное ТЗ — [`../briefs/photopult-brief.md`](../briefs/photopult-brief.md).

## Этапы

- [x] **Этап 1 — Скелет.** Проект (Kotlin/Compose/Material 3), выбор роли
      (📷 камера / 🎮 пульт), онбординг разрешений «по-человечески», проверка Google Play
      Services с честным сообщением о несовместимости, зелёный `build.yml`.
- [x] **Этап 2 — Связь.** Nearby discovery/advertising, подключение с подтверждением
      4-значного кода, автоподключение к запомненной паре, обмен `getState`/`state`,
      автоматический реконнект с восстановлением состояния. _(a) поиск+код, (b) getState/state
      + человекочитаемое имя, (fix) машина состояний подключения + ретраи 8007/8012 + пауза
      после teardown, (c) запоминание пары + автоподключение без тапов, (g) авто-реконнект +
      keep-alive. Плюс адаптивная иконка приложения._
- [x] **Этап 3 — Стрим.** H.264-превью на пульте (MediaCodec энкодер → STREAM → декодер →
      TextureView), правильная ориентация (без зеркала), зум и переключение камер, дроп
      устаревших кадров (всегда самый свежий). _CameraX Preview→энкодер (surface-input,
      low-latency), фрейминг с флагами keyframe/config, KeyframeGate для дропа, зум-слайдер и
      смена камеры с пульта, экран «Камера на связи» + затемнение, метрики стрима в отладке.
      Ориентация — device-authoritative от CameraX (`OrientationEventListener` → targetRotation →
      `TransformationInfo`), корректна при старте в портрете/ландшафте и при повороте на лету;
      кадр вписывается по месту без растяжения (letterbox); на самой камере — локальное превью
      (декод собственного потока)._
- [x] **Этап 4 — Адаптивность.** Лестница битрейта/разрешения по backlog очереди STREAM
      (1280×720@3Mbps → 960×540@1.5Mbps → 640×360@0.8Mbps), индикатор качества связи
      (3 деления), приоритет плавности над чёткостью. _Конгестия = доля времени блокировки
      записи в STREAM-пайп; `AdaptiveController` со стрик-гистерезисом (быстрый спуск,
      медленный подъём); битрейт меняется на лету, разрешение — рестартом энкодера +
      реконфигом декодера; индикатор `linkQuality` (1..3) без цифр; метрики в отладке._
- [x] **Этап 5 — Съёмка.** Спуск (полное качество сенсора через `ImageCapture`), таймер 0/3/10 с
      с крупным отсчётом на обоих экранах, серийная съёмка (удержание кнопки), сохранение в
      `DCIM/Photopult` (MediaStore), миниатюра сразу (BYTES) + фоновая передача полного фото на
      пульт (FILE), `TransferQueue` переживает реконнект. Вибрация + «Снято!» на пульте, лента
      миниатюр.
- [x] **Этап 6 — Доводка.** Вспышка (выкл/авто/вкл), tap-to-focus (маппинг тапа из превью в кадр
      сенсора + кольцо фокуса), экспокоррекция (вертикальный свайп у края), сетка 3×3, затемнение
      экрана камеры, уровень батареи камеры на пульте + предупреждение <15%, foreground service
      (тип `camera`) с уведомлением — сессия переживает звонок/сворачивание/погасший экран
      (собственный lifecycle CameraX + `PARTIAL_WAKE_LOCK`), локализация RU/EN,
      `release.yml` (подписанные APK/AAB по тегу `v*`, GitHub Release, versionCode/Name из тега),
      материалы для RuStore в `store/`. Сквозной протокол приёмки — `docs/ACCEPTANCE.md`.

## Транспорт и каналы (поверх Nearby, Strategy.P2P_POINT_TO_POINT)

- **BYTES** — команды/события (JSON, kotlinx.serialization): маленькие, приоритетные.
- **STREAM** — H.264 elementary stream превью.
- **FILE** — фоновая передача готовых фото на пульт.

Архитектура каналов проектируется так, чтобы видео добавлялось без переделки транспорта
(в MVP — только фото).

## Критерии приёмки (ориентир)

- На улице без Wi-Fi/интернета два телефона соединяются с нуля < 10 с; запомненная пара —
  < 5 с без тапов.
- Задержка превью glass-to-glass < 300 мс до ~30 м прямой видимости; деградация плавная,
  поток не рвётся.
- Реакция на зум/спуск с пульта < 200 мс.
- Фото — полное качество сенсора; копия автоматически появляется на пульте.
- Входящий звонок на камере не прерывает сессию.
- Обрыв → авто-реконнект с восстановлением состояния; недокачанные фото доезжают.
- Человек, впервые видящий приложение, делает первый удалённый снимок без инструкции.
- Нет рекламы, аналитики, сетевых запросов наружу.

## Edge cases (ориентир)

- Второй пульт при активной сессии → вежливый отказ.
- Камера занята другим приложением → внятное сообщение на обоих экранах.
- Отказ в разрешении → экран с объяснением и кнопкой в настройки, не мёртвый интерфейс.
- Переполнение хранилища при съёмке → ошибка человеческим языком.
- Устройство без Google Play Services → сообщение о несовместимости при запуске
  (не молчаливый краш).
